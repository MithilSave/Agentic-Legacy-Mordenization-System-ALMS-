# Documentation Agent — Implementation Guide

This document outlines the design, implementation, and integration of a new **Documentation Agent** into the LangGraph orchestrator pipeline. The goal of this agent is to autonomously generate READMEs, API contracts (OpenAPI/Swagger summaries), and architectural documentation for the newly refactored FastAPI microservices.

---

## 1. Responsibilities

The Documentation Agent is responsible for generating human-readable technical documentation that accompanies the generated code.

- **Service README.md**: A comprehensive overview of the microservice, how to run it (Docker), and its database requirements.
- **API Reference**: A markdown summary of the endpoints generated by the Refactoring Agent.
- **Architectural Context**: A summary of how this specific service fits into the broader ecosystem based on the Architect Agent's Domain-Driven Design boundaries.

---

## 2. State Integration (`core/constants.py`)

We need to update the global `PipelineState` and `ServiceUnit` models to accommodate the documentation output.

```python
class DocumentationOutput(BaseModel):
    service_name: str
    readme_content: str
    api_summary: str

class ServiceUnit(BaseModel):
    # ... existing fields ...
    documentation_output: Optional[DocumentationOutput] = None
```

---

## 3. Workflow Position (`core/orchestrator.py`)

The Documentation Agent should run **in parallel** with the Test-Gen Agent, directly after the Refactoring Agent successfully completes and passes its `py_compile` loop.

```mermaid
graph TD
    A[Refactoring Agent (Retry Loop)] -->|py_compile passed| B{Fork}
    B --> C[Test-Gen Agent]
    B --> D[Documentation Agent]
    C --> E{Join}
    D --> E
    E --> F[hitl_final Gate]
```

To implement this parallel fan-out inside the subgraph:
1. Update `process_service` in `core/orchestrator.py` to route to both `generate_tests` and a new `generate_docs` node.
2. Ensure both branches merge back to a synchronization node before routing to the end of the subgraph.

---

## 4. Prompt Strategy

The Documentation Agent requires context from multiple previous phases. The system prompt should enforce clear, markdown-formatted outputs.

**Inputs provided to the LLM:**
- `service_boundary`: The original DDD boundary definition from the Architect Agent.
- `generated_code`: The complete, functional Python code from the Refactoring Agent.
- `rag_docs_patterns`: (Optional) Retrieved documentation standards (e.g., standard enterprise README templates) from ChromaDB.

**Proposed System Prompt (`core/constants.py`):**
```text
DOCUMENTATION_SYSTEM_PROMPT = """You are an expert Technical Writer and Developer Advocate.

Your role: Generate comprehensive technical documentation for a newly created FastAPI microservice.

RESPONSIBILITIES:
1. Write a `README.md` explaining the service's purpose, endpoints, and how to run it via Docker.
2. Summarize the API endpoints in a markdown table.
3. Keep the tone professional, concise, and developer-friendly.

GENERATED FASTAPI CODE:
{generated_code}

SERVICE DOMAIN BOUNDARY:
{service_boundary}

Output ONLY valid JSON matching the DocumentationOutput schema."""
```

---

## 5. Output Management (`main.py`)

Finally, update `_save_outputs` in `main.py` to write the documentation files to the disk.

```python
# Save documentation
for unit in state.service_units:
    if unit.documentation_output:
        docs_dir = output_dir / unit.service.name / "docs"
        docs_dir.mkdir(exist_ok=True)
        
        readme_path = output_dir / unit.service.name / "README.md"
        readme_path.write_text(unit.documentation_output.readme_content, encoding="utf-8")
```

By following this guide, the Agentic Legacy Modernization System will not only output functional code and test suites but also comprehensive documentation, achieving a complete software lifecycle migration.
