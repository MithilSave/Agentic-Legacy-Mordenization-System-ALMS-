## Figure: dependency graph before/after deterministic filtering

Task 1.2. No LLM required.

```bash
python paper/figures/gen_graph_before_after.py
```

Outputs `paper/figures/graph_before_after.pdf` and `paper/figures/graph_stats.txt`.

**Recorded values (run 2026-08-28, commit on `fix/pipeline-emit-generated`):**

```
source examples/sample_monolith
nodes_before 134
edges_before 251
hotspots_before 6
nodes_after 75
edges_after 104
hotspots_after 2
node_reduction_pct 44.0
edge_reduction_pct 58.6
```

Paper phrasing: deterministic filtering removes 44% of graph nodes and 59% of
edges (Python builtins, stdlib method calls, local-variable method calls that
are not architectural dependencies), collapsing 6 spurious coupling "hotspots"
to the 2 real god-modules (`app`, `orders`).

Interpretation for the paper: the "Unfiltered" graph is the pre-fix
`build_dependency_graph` behaviour (an edge to every unresolved call name, including
Python builtins, stdlib method calls, and local-variable methods). The "Filtered"
graph is the current implementation. The reduction is the evidence for RQ3.
